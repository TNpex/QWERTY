# SaleTennis BI Analytics

BI-дашборд для анализа наличия товаров и размеров по магазинам сети SaleTennis.

**Данные уже встроены в сайт** (`public/data/`: каталог из 1265 товаров, остатки по
размерам в 10 магазинах и история снимков) — дашборд открывается сразу с реальной
картиной остатков. Можно загрузить и свой XLSX/CSV-файл.

Что показывает сайт: KPI-обзор, таблицу наличия по размерам со ссылками на товары,
**продажи и распроданные товары** (по ежедневным снимкам парсинга), рекомендации по
перемещению товара между магазинами и по дозакупке у поставщика, графики.

Данные обрабатываются **полностью в браузере** (файлы никуда не отправляются);
загруженный вручную файл сохраняется в IndexedDB и переживает перезагрузку страницы.

## 📦 Данные сайта и история снимков

Актуальные данные лежат прямо в репозитории, в `public/data/` — сайт показывает их
сразу при открытии, без ручной загрузки файла:

```
public/data/
├── products.csv           ← актуальный каталог (широкий формат: магазины-колонки)
├── sizes.csv              ← актуальные остатки по размерам (Размер/Магазин/Количество)
└── history/
    ├── manifest.json      ← список снимков [{ file, date }]
    └── 2026-09-23.csv     ← снимок остатков за дату (формат products.csv)
```

- Остатки по размерам берутся из `sizes.csv` (точный источник), каталог товаров —
  из `products.csv`. Файлы сверяются по колонке «Ссылка» (уникальный идентификатор
  товара; «Артикул» уникальным НЕ является — у цветовых вариантов он общий).
- Размер «375» в sizes.csv автоматически нормализуется в «37,5» (при экспорте
  теряется запятая), «Без размера» → «—».
- Для каждого товара материализуются нули отсутствующих размеров в магазинах,
  которые его возят — так видны «дыры» в размерных сетках (37% SKU сейчас с нулём).

### Ежедневное обновление (история продаж)

Сохраняйте результат каждого парсинга saletennis.com в CSV и добавляйте в историю:

```bash
npm run snapshot -- ~/загрузки/2026-09-24.csv
```

Скрипт сам:
1. положит снимок в `public/data/history/2026-09-24.csv` (дата — из аргумента или имени файла);
2. обновит `manifest.json` и `products.csv`;
3. если подать sizes.csv (длиный формат) — обновит только `sizes.csv`.

После этого закоммитьте данные: `git add public/data && git commit -m "data: снимок 2026-09-24"`.

Когда снимков ≥ 2, вкладка **🔥 Продажи** показывает: продано единиц за период,
лидеров продаж (шт/день), перемещения между магазинами, поступления и — главное —
**распроданные товары** (остаток был > 0 и стал 0, либо товар исчез из каталога).
С одним снимком на вкладке видны товары с нулевым остатком на текущий момент.

### Фотографии товаров

Основной источник фото — **ваш парсер**: он сохраняет картинки в папку `Product_images`
(имена файлов совпадают с колонкой «Фото» в products.csv, например
`data\product_images\943ea3091107.png`). Скопируйте папку в проект один раз:

```bash
npm run images -- C:\путь\к\Product_images
```

Скрипт положит файлы в `public/data/product_images/` (повторный запуск копирует только
новое), сверит покрытие с каталогом и напечатает объём. Сайт берёт фото **локально** —
это быстро и не зависит от доступности saletennis.com.

Резервный источник — `public/data/product-images.json` (карта «ссылка → фото на сайте»,
создана `npm run scrape-images`). Используется только для товаров, у которых нет
локального файла; каскад: локальное фото → фото с сайта → заглушка.

> ⚠️ **Размер репозитория**: если папка фото больше ~100 МБ, git push станет долгим,
> а хостинг — тяжёлым. В этом случае сожмите изображения (XnConvert/ImageMagick:
> ширина 600px, WebP q80 — обычно даёт 10–30 МБ на весь каталог) или храните фото
> вне git (object storage / CDN) и пропишите их URL в отдельном файле карты.

## 📁 Форматы файлов

Парсер автоматически определяет один из двух форматов. Названия колонок распознаются гибко
(«товар / название / наименование / name», «количество / кол-во / остаток / quantity» и т.д.).

### Формат A — «длинный» (рекомендуемый)

Одна строка = один остаток. Повторяющиеся строки (тот же товар+магазин+размер) суммируются.

| Товар * | Размер | Магазин * | Количество * | Бренд | Категория | Цена | Артикул |
|---|---|---|---|---|---|---|---|
| Кроссовки Nike | 42 | ТЦ Европа | 3 | Nike | Обувь | 8990 | NK-1 |
| Кроссовки Nike | 43 | Склад | 5 | Nike | Обувь | 8990 | NK-1 |

Комбинации, которых нет в файле, считаются «магазин не возит» и показываются как «—»
(они **не** влияют на процент «нет в наличии» и не порождают рекомендаций по перемещению).

### Формат B — «широкий»

Магазины — отдельные колонки. Наличие по размерам — либо текстовая колонка «Размеры и наличие»:

```
43: Санкт-Петербург (Спортивная) - 2 шт | 44: Екб_Склад - 1 пар
```

либо просто числа в колонках магазинов (тогда размер не учитывается).

| Категория | Артикул | Название * | Бренд | Цена | Размеры и наличие | Спб_Спортивная | Екб_Склад |
|---|---|---|---|---|---|---|---|
| Обувь | NK-1 | Кроссовки Nike | Nike | 8990 | 43: Спб_Спортивная - 2 шт | 2 | |

Пустая ячейка в колонке магазина = магазин не возит товар («—»). Явный `0` = «нет в наличии».

### CSV

Разделитель (`,` `;` табуляция `|`) определяется автоматически — файлы из русского Excel
(с `;`) работают. Поддерживаются кавычки, экранированные `""`, переносы `\r\n` и BOM.

## 🧮 Как считается аналитика

Все константы — в `src/utils/analyticsCore.ts`:

| Константа | Значение | Смысл |
|---|---|---|
| `MIN_PER_STORE` | 2 | норматив запаса на каждый **возящий** магазин на размер (дозакупка) |
| `STORE_EXCESS_TRIGGER` | 4 | ≥ 4 шт одного размера в магазине — переизбыток (донор перемещения) |
| `DONOR_KEEP` | 3 | сколько единиц донор оставляет себе |
| `RECIPIENT_LOW` | 1 | остаток ≤ 1 шт — «мало», магазин-получатель |
| `TRANSFER_CAP` | 3 | максимум единиц в одном перемещении между магазинами |
| `POPULAR_SIZES` | 41–44, M, L, XL | ходовые размеры → повышенный приоритет перемещения |
| `OOS_WARN_PERCENT` / `OOS_BAD_PERCENT` | 15 / 30 | пороги жёлтого/красного статуса магазина |

**Перемещения** работают по бизнес-правилам сети:
1. **Склад → магазины**: размер лежит на складе, а в магазине его нет — везём до норматива
   (основной поток, 📦);
2. **Переизбыток → дефицит**: в магазине ≥ 4 шт одного размера — отдаёт (оставляя себе 3)
   в магазины своего города, где размера нет или ≤ 1 шт;
3. **Логистика**: маршруты помечаются — «внутри города» (дёшево), «между городами» (платно),
   «из СПб в другой город» (💸 дорого — **скрыты по умолчанию**: обычно выгоднее дозаказать
   у поставщика; включаются отдельным переключателем с предупреждением).

Магазины на всех вкладках упорядочены по городам (СПб → Екб → Тюмень → Уфа → Ижевск),
**склад — всегда последний и выделен синим 📦**.

**Дозакупка** — детерминированная (никаких случайных чисел), с фильтрами **по бренду и
категории** и выгрузкой заявки поставщику в **XLSX**. Перед заказом дефицит проверяется на
покрытие перемещением (со склада или из переизбытка магазинов) — в заявку попадает только
то, что реально нужно купить:
- `critical` — товар полностью отсутствует во всех возящих магазинах;
- `high` — покрытие норматива < 50% либо более половины размеров с нулём по сети;
- `medium` — остальное.

Прогноз «дней до исчерпания» появится после накопления истории продаж (вкладка «Продажи»).

**Производительность**: все расчёты используют предварительно построенные Map-индексы
(один проход O(N) вместо вложенных `find()`), поэтому 160 000 записей инвентаря
обрабатываются за доли секунды. Есть регрессионный тест производительности.

```
public/data/                       ← ⭐ данные сайта (каталог, размеры, история, фото)
scripts/
├── add-snapshot.mjs               ← npm run snapshot — снимок остатков в историю
└── scrape-images.mjs              ← npm run scrape-images — сбор фото товаров
src/
├── App.tsx                        ← навигация (6 вкладок), сайдбар, экран загрузки
├── main.tsx                       ← точка входа
├── types.ts                       ← доменные типы (Store, Product, InventoryItem, ...)
├── context/
│   └── DataContext.tsx            ← состояние: встроенные/загруженные данные, история,
│                                    карта фото, автосохранение в IndexedDB
├── hooks/
│   └── useAnalytics.ts            ← мемоизированные хуки метрик, рекомендаций, продаж
├── utils/
│   ├── analyticsCore.ts           ← ⭐ все расчёты (чистые функции) + константы
│   ├── storeGroups.ts             ← города магазинов, склад, маршруты перемещений
│   ├── bundledData.ts             ← ⭐ слияние products.csv + sizes.csv → ParsedData
│   ├── historyCore.ts             ← ⭐ снимки истории: продажи/перемещения/распродано
│   ├── images.ts                  ← карта фотографий товаров
│   ├── xlsxParser.ts              ← парсер XLSX/CSV (длинный и широкий форматы)
│   ├── csv.ts                     ← CSV-парсер (автоопределение разделителя, кавычки)
│   ├── sizes.ts                   ← нормализация и сортировка размеров
│   └── storage.ts                 ← IndexedDB-обёртка (переживает перезагрузку)
└── components/
    ├── FileUpload.tsx             ← экран загрузки с документацией форматов
    ├── Dashboard.tsx              ← KPI-карточки (включая «Распродано») и обзор
    ├── InventoryTable.tsx         ← таблица наличия: карточка товара по клику,
    │                                фильтр «только распроданные», пагинация
    ├── ProductCardModal.tsx       ← ⭐ карточка товара: фото, наличие, размерная сетка
    ├── SalesHistory.tsx           ← вкладка «Продажи»: движение товаров по снимкам
    ├── TransferRecommendations.tsx← перемещения: фильтры, маршруты, переизбыток
    ├── RestockRecommendations.tsx ← дозакупка: фильтры, покрытие, XLSX-заявка
    └── Charts.tsx                 ← графики (Recharts)
```

Юнит-тесты лежат рядом с кодом: `src/utils/*.test.ts` (78 тестов: CSV, парсер,
форматы, слияние данных, аналитика, маршруты, история продаж, производительность).

| 🛒 Дозакупка | Фильтры **по бренду и категории**, покрытие перемещением, **выгрузка заявки поставщику в XLSX** |
| 📈 Аналитика | Графики: магазины, категории, размеры, статус наличия (SKU) |

## 🔧 Технологии

- **React 18 + TypeScript (strict)** — UI
- **Vite 6** — сборщик
- **Tailwind CSS 4** — стили
- **Recharts** — графики
- **SheetJS (xlsx 0.20.x)** — парсинг Excel, динамический импорт (грузится только при загрузке файла)
- **Vitest / ESLint / GitHub Actions** — тесты, линтинг, CI

> Примечание: `xlsx` установлен с официального CDN SheetJS
> (`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`) — в npm-регистре версия
> 0.18.5 с неисправленными уязвимостями (CVE-2023-30533, CVE-2024-22363).
