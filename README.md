# SaleTennis BI Analytics

BI-дашборд для анализа наличия товаров и размеров по магазинам сети SaleTennis.

Загружаете XLSX/CSV-файл с остатками — получаете KPI-обзор, таблицу наличия по размерам,
рекомендации по перемещению товара между магазинами и по дозакупке у поставщика, графики.

Данные обрабатываются **полностью в браузере** (файл никуда не отправляется) и сохраняются
в IndexedDB — при перезагрузке страницы восстанавливаются автоматически.

## 📁 Форматы файлов

Парсер автоматически определяет один из двух форматов. Названия колонок распознаются гибко
(«товар / название / наименование / name», «количество / кол-во / остаток / quantity» и т.д.).

### Формат A — «длинный» (рекомендуемый)

Одна строка = один остаток. Повторяющиеся строки (тот же товар+магазин+размер) суммируются.

| Товар * | Размер | Магазин * | Количество * | Бренд | Категория | Цена | Артикул |
|---|---|---|---|---|---|---|---|
| Кроссовки Nike | 42 | ТЦ Европа | 3 | Nike | Обувь | 8990 | NK-1 |
| Кроссовки Nike | 43 | Склад | 5 | Nike | Обувь | 8990 | NK-1 |

Комбинации, которых нет в файле, считаются «магазин не возит» и показываются как «—»
(они **не** влияют на процент «нет в наличии» и не порождают рекомендаций по перемещению).

### Формат B — «широкий»

Магазины — отдельные колонки. Наличие по размерам — либо текстовая колонка «Размеры и наличие»:

```
43: Санкт-Петербург (Спортивная) - 2 шт | 44: Екб_Склад - 1 пар
```

либо просто числа в колонках магазинов (тогда размер не учитывается).

| Категория | Артикул | Название * | Бренд | Цена | Размеры и наличие | Спб_Спортивная | Екб_Склад |
|---|---|---|---|---|---|---|---|
| Обувь | NK-1 | Кроссовки Nike | Nike | 8990 | 43: Спб_Спортивная - 2 шт | 2 | |

Пустая ячейка в колонке магазина = магазин не возит товар («—»). Явный `0` = «нет в наличии».

### CSV

Разделитель (`,` `;` табуляция `|`) определяется автоматически — файлы из русского Excel
(с `;`) работают. Поддерживаются кавычки, экранированные `""`, переносы `\r\n` и BOM.

## 🧮 Как считается аналитика

Все константы — в `src/utils/analyticsCore.ts`:

| Константа | Значение | Смысл |
|---|---|---|
| `MIN_PER_STORE` | 2 | норматив запаса на каждый **возящий** магазин на размер (дозакупка) |
| `TRANSFER_CAP` | 3 | максимум единиц в одном перемещении |
| `POPULAR_SIZES` | 41–44, M, L, XL | ходовые размеры → повышенный приоритет перемещения |
| `OOS_WARN_PERCENT` / `OOS_BAD_PERCENT` | 15 / 30 | пороги жёлтого/красного статуса магазина |

**Перемещения** — жадный алгоритм: донор оставляет себе запас не ниже среднего по сети,
один и тот же остаток не «обещается» дважды, получатели — только магазины с нулевым
остатком, которые возят товар. Приоритет: ходовой размер + обувь → высокий.

**Дозакупка** — детерминированная (никаких случайных чисел):
- `critical` — суммарный остаток товара равен нулю;
- `high` — покрытие норматива < 50% или более половины размеров с нулём по сети;
- `medium` — остальное.

Прогноз «дней до исчерпания» намеренно не показывается: без истории продаж он был бы
выдумкой. Подключите источник продаж (см. Дорожную карту) — и метрика станет честной.

**Производительность**: все расчёты используют предварительно построенные Map-индексы
(один проход O(N) вместо вложенных `find()`), поэтому 160 000 записей инвентаря
обрабатываются за доли секунды. Есть регрессионный тест производительности.

## 📂 Структура проекта

```
src/
├── App.tsx                        ← навигация, сайдбар, экран загрузки/сплэш
├── main.tsx                       ← точка входа
├── types.ts                       ← доменные типы (Store, Product, InventoryItem, ...)
├── context/
│   └── DataContext.tsx            ← состояние данных + автосохранение в IndexedDB
├── hooks/
│   └── useAnalytics.ts            ← мемоизированные хуки метрик и рекомендаций
├── utils/
│   ├── analyticsCore.ts           ← ⭐ все расчёты (чистые функции) + константы
│   ├── xlsxParser.ts              ← парсер XLSX/CSV → ParsedData (оба формата)
│   ├── csv.ts                     ← CSV-парсер (автоопределение разделителя, кавычки)
│   ├── sizes.ts                   ← естественная сортировка размеров
│   └── storage.ts                 ← IndexedDB-обёртка (переживает перезагрузку)
└── components/
    ├── FileUpload.tsx             ← экран загрузки с документацией форматов
    ├── Dashboard.tsx              ← KPI-карточки и обзор по магазинам
    ├── InventoryTable.tsx         ← таблица наличия с раскрытием по размерам
    ├── TransferRecommendations.tsx
    ├── RestockRecommendations.tsx
    └── Charts.tsx                 ← графики (Recharts)
```

Юнит-тесты лежат рядом с кодом: `src/utils/*.test.ts` (45 тестов: CSV, парсер,
форматы, аналитика, производительность).

## 🔧 Технологии

- **React 18 + TypeScript (strict)** — UI
- **Vite 6** — сборщик
- **Tailwind CSS 4** — стили
- **Recharts** — графики
- **SheetJS (xlsx 0.20.x)** — парсинг Excel, динамический импорт (грузится только при загрузке файла)
- **Vitest / ESLint / GitHub Actions** — тесты, линтинг, CI

> Примечание: `xlsx` установлен с официального CDN SheetJS
> (`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`) — в npm-регистре версия
> 0.18.5 с неисправленными уязвимостями (CVE-2023-30533, CVE-2024-22363).
